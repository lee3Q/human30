# stages/ — 무대 카탈로그

각 무대는 30명이 들어가는 *공간·시간·제약 조건*을 정의한다. 30p의 원칙: **30인 본질은 불변, 무대는 가변**. 같은 시드의 30명을 학원/회사/재난 대피소/우주선 등 여러 무대에 던질 수 있다.

## 무대 파일 구조

`stages/S{XX}_{slug}.md` 형식. 각 파일은 다음 섹션 포함:

1. **이름 + 한 줄 요약**
2. **공간** — 물리적 배치, 좌석 구조, 거리/볼륨 단계 (whisper/talk/loud)
3. **시간** — 시뮬 내부 시작 시각, 예상 지속 시간
4. **제약 조건** — 30명이 왜 여기 모여있는가, 나갈 수 있는가, 외부와 연결되는가
5. **기본 리듬** — 수업/식사/쉬는 시간 등 *tick을 나누는 블록*
6. **초기 긴장 축** — 이 무대가 자연스럽게 유발하는 대립/동맹/위계
7. **권위자·외부자** — 강사/상사/관리자 등 30명 외 존재의 등장 빈도와 역할
8. **폰 사용 가능성** — 이 무대에서 휴대폰을 쓸 수 있는가, 언제
9. **자원** — 식수·음식·화장실·침대·인터넷 등 유무
10. **고유 시나리오 제안** — 이 무대에 특히 어울리는 시나리오 힌트

## 현재 무대 (04-08 시점)

- `S01_jaesu_academy.md` — 재수학원 자습실 ✓
- *S02 / S03 미작성* — 첫 시뮬 후 필요 시 추가 (회사 워크숍, 재난 대피소 등)

## 무대 결정 원칙

- **핍진성**: 30명이 *자연스럽게 모일 이유*가 있어야 한다. 억지 시나리오 금지
- **나갈 수 없음 또는 나가기 어려움**: 시뮬레이션의 긴장은 *공간 폐쇄성*에서 나온다
- **시간 압력 옵션**: 무대 자체에 *데드라인*(다음 모의고사·퇴근·구조대 도착 등)이 있으면 행동 가속
- **권위자 최소화**: 시뮬의 핵심은 *30명 내부 상호작용*. 권위자는 개입 최소

## 시드 × 무대 × 시나리오 조합

```
사용자 호출 예:
시드 1 + S01 재수학원 + S001-A 처형 투표 시나리오 시동
시드 1 + S01 재수학원 + 일상 기본 (시나리오 없음, 관찰만)
시드 42 + S01 + S001-B 공개 투표 버전
```

같은 시드(30명)에 여러 무대·시나리오를 실험 가능. 결과 파일은 `runs/seed_N_S{stage}_S{scenario}.json` 같은 파생으로.
