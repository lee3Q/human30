# UX Design Harness — 30p 시뮬 모드 분리 + 세션 플로우 확정

**용도**: 30p를 **작업 모드**(설계/고치기/옵션표)와 **시뮬 모드**(play/x-ray/phone/무의식)로 *폴더 단위로 분리*하고, 시뮬 모드의 게임 UX 작동방식을 확정. alias 정비까지 포함.

**실행 방법**: 새 Claude Code 세션을 `~/pp/30p` 에서 시작 → 첫 메시지로 이 파일 붙여넣기 (또는 `@harnesses/ux_design.md` 참조) → 섹션별 대화 진행 → 세션 끝에 `git commit`.

**작업 원칙**:
- **Claude가 먼저 초안, 사용자가 섹션별 수정**. "어떻게 할까요?" 금지. 먼저 초안을 내놓고 "이대로 OK? 수정?" 물어야 함
- **섹션 단위로 확정**. 한 섹션 OK 받고 다음 섹션으로
- **과잉 설계 금지**. 실제 사용 경험이 드러낼 필요에 맞춰서만
- **코드 0**. 문서만 (CLAUDE.md 2개 + session_flow.md + alias 제안)

## 배경 (세션 시작 시 반드시 읽을 것)

### 프로젝트 상태
- `~/pp/30p/CLAUDE.md` — 작업 모드 기본 규칙
- `~/pp/30p/.state/current.md` — 현재 스냅샷
- `~/pp/30p/.state/queue.md` — 작업 큐
- `~/pp/30p/runs/seed_001_S002_vote1.md` — 첫 시뮬 결과 (참고)

### 2026-04-09 대화 중 확정된 것 (이 하네스의 전제)

1. **자동 tick 시뮬 아님** — 사용자 호출 기반 이벤트 체인. 사용자는 세계를 멈춤·재개할 수 있는 감독
2. **외피(드러난 행동) + 내면(생각·감각·기억) 동시 생성** — 한 번의 `play` 호출에서 Claude가 참여자 전원의 내면과 외피를 *동시에* 생성해 파일로 박음. 내면은 외피의 *근거*. 사용자 x-ray 호출 시 *재생성 없이* 파일 읽기만 (사후 합리화 금지)
3. **두 축 누적**: 세계 축(`timeline.md`) + 캐릭터 축(`memories/<id>.md`). 직교
4. **폴더로 모드 분리**: 작업 폴더와 시뮬 폴더가 분리돼서 `cd` 만으로 세션 모드가 정해짐. alias도 정비
5. **요약·근사·필터링 금지** — 30인 복수성 훼손은 본질 상실
6. **리서치 합성**: `~/pp/30p/research/인간30에이전트2/synthesis.md` (참고 자료, 재해석 금지)

### 섹션 1: Alias 정비

**Claude가 먼저 확인할 것** (세션 시작 후):
```bash
cat ~/.zshrc | grep -E "(alias|export)" 
```
현재 alias 목록을 파악해서 **어떤 게 부족한지**, **어떤 게 중복·오류인지** 판정.

**Claude가 먼저 제안할 초안** (수정 필요하면 사용자와 조율):
```bash
# 30p 워크스페이스 진입
alias pp='cd ~/pp'
alias nn='cd ~/pp/30p'        # 30p 작업 모드 (default)
alias ss='cd ~/pp/30p/play'   # 30p 시뮬 모드

# Claude Code 켜기 (별도)
# cc 는 이미 있으면 건드리지 말 것
```

**사용자 메모리 원칙** (`feedback_alias_convention.md`): *"alias는 cd만, cc로 별도 시작"*. 이 원칙을 지키며 정비.

**작업 순서**:
1. `~/.zshrc` 현재 상태 읽기 (수정 전)
2. 부족·오류 목록 정리
3. 사용자에게 제안안 제시 (diff 스타일)
4. 사용자 승인 후 파일 수정
5. `source ~/.zshrc` 는 사용자가 직접 (새 터미널 여는 게 깔끔)

**사용자 피드백 항목**:
- alias 이름 (nn, ss가 편한가?)
- 기존 쓸데없는 alias 정리 범위

### 섹션 2: 명령 어휘 표

**Claude가 먼저 제안할 초안** (수정 예상):

| 어휘 | 의미 | 예시 |
|---|---|---|
| `이어서` / `시뮬 시작` / `다음` | 현재 세계 상태 + 다음 장면 후보 3~5개 제시 | `이어서` |
| `[시간] @ [무대] "[사건]"` | play 호출 — 외피+내면 동시 생성 | `5분 @ 강당 "투표 발표"` |
| `[시간]` (무대·사건 생략) | 직전 무대 연장, 변화 없음, 시간만 흐름 | `10분` |
| `x #N` / `x-ray #N` | #N 내면 읽기 (파일 읽기만, 재생성 없음) | `x #9` |
| `폰 #N` / `phone #N` | #N 폰 상태·이력 | `폰 #9` |
| `무의식 #N` / `sub #N` | #N 접근 불가 영역 | `무의식 #9` |
| `되돌려 [지점]` | 특정 시점 되감아 재굴림 | `되돌려 투표 직전` |

**어휘 해석 원칙**:
- 자연어 변형 허용. `#9 폰 좀 보여줘` / `9번 폰` / `phone 9` 다 OK
- 표는 *권장 표기*일 뿐 강제 문법 아님
- 해석 모호하면 Claude가 "이렇게 해석했는데 맞나?" 한 번 확인

**사용자 피드백 항목**:
- 어휘 이름 (한국어/영어 혼용 OK인가?)
- 약어 범위 (`x`, `sub` 이런 짧은 것 OK?)
- `되돌려` 같은 건 나중에 쓸 일이 있을지

### 섹션 3: 시간 단위·세계 시계

**Claude가 먼저 제안할 초안**:

- **입력은 자유**: `5분`, `한 시간`, `다음 날 아침`, `투표 발표 직후 10분`
- **내부 변환**: Claude가 파일 헤더에 **절대 시계**로 기록. 예: `D1 16:00~16:05`
- **D1/D2** = 시나리오 Day 1, Day 2
- **세계 시계 시작점**: 시나리오 첫 play 때 사용자에게 "D1 몇 시부터 시작?" 물어봄
- **이후**: Claude가 자동으로 이어 계산. 사용자는 절대 시계 기억할 필요 없음

**사용자 피드백 항목**:
- `D1 16:00` 표기 형식 OK?
- 시나리오 경계 규칙 (S002가 끝나고 S003이 시작할 때 시간 이어감? 초기화?)

### 섹션 4: play 호출 처리 흐름

**Claude가 먼저 제안할 초안**:

사용자가 `5분 @ 강당 "투표 발표"` 치면:

**1. 참조 파일 읽기**:
- `~/pp/30p/runs/seed_001.json` — 30명 시드
- `~/pp/30p/stages/S01_jaesu_academy.md` (또는 지정 무대 파일)
- `~/pp/30p/runs/seed_001/timeline.md` 최근 섹션 (있으면)
- 이전 `scenes/*/interior/<id>.md` 중 *직전 play에 참여한 캐릭터*만 선택적으로 (해당 장면에 그들이 뭘 생각했는지 연속성 유지용)

**2. 내부 생성** (한 번에):
- 무대에 있는 전원 (투표 발표 시 = 강당의 30명) 각자의 **그 5분간 내면 서사** 생성 (각자 400~1200자, 수사기록 톤)
- 각자의 내면이 낳는 **드러난 행동**을 추출해 외피 타임라인 구성

**3. 파일 저장**:
```
runs/seed_001/scenes/play_003_D1_16h00_vote_result/
├── surface.md                    ← 외피 타임라인
├── interior/
│   ├── 01.md  03.md  ...  30.md  ← 참여자 각자 내면
├── phone/
│   └── 09.md 23.md ...           ← 폰 만진 사람만
└── subconscious/
    └── 09.md 23.md ...           ← 본인 접근 불가 반응 있을 때만
```

**4. timeline.md 갱신**:
- `runs/seed_001/timeline.md` 에 외피 섹션 append (`surface.md` 와 동일 내용)

**5. 화면 자동 출력**: **외피 타임라인만**. 내면은 "저장됨. `x #N` 으로 조회 가능" 정도만 언급.

**사용자 피드백 항목**:
- 참여자 판정 규칙 (강당 기준? 전원 기준?)
- 파일 명명 (`play_003_D1_16h00_vote_result`) 너무 길어?
- 자동 출력이 외피만이어도 답답하지 않을지

### 섹션 5: 관찰 명령 흐름

**Claude가 먼저 제안할 초안**:

사용자가 `x #9` 치면:
1. 직전 play 폴더에서 `interior/09.md` 읽기 (재생성 없음)
2. 그대로 화면 출력
3. `runs/seed_001/memories/09.md` 에 "`## [D1 16:00~16:05] 투표 발표 / interior`" 섹션 append (캐릭터 축 누적)

사용자가 `x #9 @ 투표 직전` 치면:
1. 해당 시점의 play 폴더 찾기 (timeline.md 에서 역검색)
2. 해당 폴더의 `interior/09.md` 읽기

`폰 #9` / `무의식 #9` 도 동일 패턴 (경로만 `phone/` / `subconscious/`).

**사용자 피드백 항목**:
- 시점 지정 문법 (`@ 투표 직전`, `@ last`, `@ D1 16:00` 등)
- `memories/` append 여부 (관찰이 기록으로 남아야 하나 휘발이어도 되나?)

### 섹션 6: 세션 시작 반응 규칙 (시뮬 모드)

**`30p/play/CLAUDE.md` 에 박을 내용** (초안):

사용자 첫 메시지가 *시뮬 관련* 이면 (`시뮬 시작`, `이어서`, `다음`, `N분 @...` 등) Claude가 자동으로:

1. `.state/current.md` + `runs/timeline.md` 마지막 섹션 읽기
2. 다음 응답으로:
```
현재 세계: seed_001, 무대 [S01 재수학원 강당]
마지막 사건: [play_002_D1_16h00_vote1] — 투표 과정 완료
세계 시계: D1 16:00 직전 (투표 발표 직전)

다음 장면 후보:
  1. [D1 16:00~16:05] 발표 직후 5분 — 드러난 반응만
  2. [D1 16:00~17:00] 발표 후 1시간 — 퇴장·복도
  3. [D2 08:00~08:30] 다음 날 아침
  4. 특정 캐릭터 관찰 — x/폰/무의식 #N
  5. 직전 투표 결과 검증
  6. 새 시나리오

번호 또는 자유 지시.
```

사용자 첫 메시지가 *구체 지시* 이면 (예: `5분 @ 강당 "발표"`) 바로 수행 (선택지 제시 생략).

**사용자 피드백 항목**:
- 선택지 개수 (3~5개 적당?)
- 어감·문체 (사무 톤 vs 편한 톤)
- 세계 상태 요약 줄 수

### 섹션 7: 외피 타임라인 포맷

**Claude가 먼저 제안할 초안** (`surface.md`):

```markdown
# [D1 16:00~16:05] 재수학원 강당, 투표 발표 직후

## 무대
- 30명 전원 강당 착석. 사회자 #22 단상
- 투표지 수거 완료, 결과 발표 직전

## 타임라인

- **16:00:00** 사회자 #22 마이크 ON. "결과 발표합니다" 손 미세 떨림
- **16:00:47** "#9 → #21" 호명. #9 고개 숙임, 양손 책상 밑
- **16:01:12** "#23 → #14" 호명. #23 3초 정지. 주변 시선 몰림
- **16:01:30** #14 고개 들어 #23 방향 쳐다봄. 짧음
- **16:02:05** #17 "화장실요" 일어섬. 의자 끄는 소리
- **16:02:40** #21 책상 위 손가락 두 번 까딱임. 정면 응시
- **16:04:30** #9 종이 없이 이름 쓰는 시늉
- **16:04:55** 발표 완료. 사회자 "해산" 선언
```

**톤 원칙**:
- 수사기록, 건조, 동정 0, 해석 0
- 문장 짧게. 주어 생략 허용
- 시간은 `HH:MM:SS` 단위 (단 매 초 기록 아님, 유의미한 순간만)
- 관찰 가능한 것만 (표정·동작·말·공간 변화). *마음*은 interior에만.

**사용자 피드백 항목**:
- 포맷 구조 (무대/타임라인 구분이 유용한지)
- 시간 표기 방식
- "해석 0" 원칙이 어디까지인지 (예: "주변 시선 몰림"은 해석인가 관찰인가)

### 섹션 8: 내면 (interior) 포맷
