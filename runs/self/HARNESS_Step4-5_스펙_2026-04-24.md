## Step 4: 테스트 — 자기 카톡 재실행 + 타인 카톡 검증

### 목적
MVP가 기존 프로토타입 세션(4d3cdc38)과 동일한 발견을 재생산하는지 확인. 그리고 *다른 사람*의 카톡에서도 유효한 발견을 만드는지 검증.

### 서브태스크

#### 4-1. 본인 카톡 재실행
- **입력**: 이상규 본인 카톡 csv (프로토타입에서 사용한 것과 동일 또는 신규)
- **전제**: 이상규가 직접 카톡 csv를 제공해야 함. Opus가 임의로 접근 금지.
- **프로세스**:
  1. `analyze_kakao.py` 범용화 버전 실행 (이상규 전화번호 하드코딩 제거)
  2. LLM 해석 프롬프트(범용화 버전)로 발견 5개 생성
  3. 프로토타입 발견(`discoveries/01~06*.md`)과 비교
- **출력**: `runs/harness_test/self_test_결과.md` — 재생산율(5개 중 N개 일치) + 신규 발견 + 누락

#### 4-2. 타인 카톡 실행
- **입력**: 이상규가 제공하는 타인 카톡 csv (친구·가족 등, 동의 획득 필수)
- **프로세스**:
  1. 동일 스크립트 + 동일 프롬프트로 실행
  2. 발견이 *그 사람에게만 해당하는* 것인지 확인 (이상규 발견과 중복 안 됨)
- **출력**: `runs/harness_test/other_test_결과.md` — 타인 발견 5개 + 이상규 발견과의 차이점

#### 4-3. 비교 분석
- **입력**: 4-1 + 4-2 결과
- **프로세스**:
  1. 발견의 *범용성* 평가: "XX 비율이 낮다"가 모든 관계에서 나오는지, 특정 관계에서만 나오는지
  2. 프롬프트의 *편향* 점검: 이상규 특화 발견이 타인에게도 강제 생성되는지
- **출력**: `runs/harness_test/comparison.md` — 범용성 점수 + 편향 탐지 결과

### 입력 정의
| 입력 | 형식 | 필수 | 비고 |
|------|------|------|------|
| 카톡 csv | CSV (카카오톡 내보내기 형식) | Yes | UTF-8 또는 UTF-16 |
| 본인 전화번호 | String | Yes | sender 구분용 |
| 상대방 이름 | String | No | 익명화 가능 |

### 출력 정의
| 출력 | 형식 | 위치 |
|------|------|------|
| 파싱 통계 | JSON | `runs/harness_test/stats/` |
| 발견 목록 | Markdown | `runs/harness_test/discoveries/` |
| 비교 분석 | Markdown | `runs/harness_test/comparison.md` |

### 완료 기준
1. 본인 카톡에서 프로토타입 발견 5개 중 3개 이상 재생산
2. 타인 카톡에서 *그 사람에게만 해당하는* 발견 3개 이상 생성
3. 프롬프트 편향(이상규 특화 발견 강제 생성) 미탐지

### 잠재 실패 모드

| 실패 모드 | 징후 | 대응 |
|-----------|------|------|
| 재생산율 < 60% | 범용화 과정에서 핵심 로직 손실 | 프로토타입 스크립트와 diff 비교 |
| 타인 발견 = 일반론 | "이 사람은 배려심이 있다" 수준 | 프롬프트에 구체적 패턴 요구 추가 |
| 프롬프트 편향 | 타인에게도 이상규 발견과 유사한 결과 | 이상규 특화 컨텍스트 잔여 확인 |
| 카톡 형식 불일치 | 파싱 에러 | 카카오톡 버전별 형식 차이 대응 |
| 개인정보 노출 | 통계에 전화번호·실명 포함 | 파싱 직후 익명화 처리 |

## Step 5: 송명기 대표 시연

### 목적
제품이 실제로 작동하는 모습을 타인에게 보여주어 (a) 피드백 획득 (b) 사업 가능성 탐색.

### 서브태스크

#### 5-1. 시연 준비
- **입력**: Step 4에서 검증된 MVP
- **프로세스**:
  1. 시연용 깨끗한 카톡 샘플 준비 (이상규 본인 것, 민감 정보 제거)
  2. 시연 스크립트 작성: "이게 뭔지" → "어떻게 작동하는지" → "결과물" → "가치 제안"
  3. 예상 질문 5개 준비 + 답변
- **출력**: `runs/harness_demo/시연스크립트.md`

#### 5-2. 시연 실행
- **전제**: 송명기 대표와의 미팅 일정 확정 필요. Opus가 임의로 일정 잡을 수 없음.
- **프로세스**:
  1. 라이브 시연: 대표 카톡(동의 시) 또는 샘플 카톡으로 5분 실행
  2. 결과물 즉시 보여주기
  3. 피드백 수집: "쓸모 있나?" "무엇이 부족한가?" "얼마면 사겠는가?"
- **출력**: `runs/harness_demo/시연결과.md` — 대표 반응 + 피드백 + 다음 단계

#### 5-3. 피드백 정리
- **입력**: 5-2 결과
- **프로세스**:
  1. 피드백을 발견·제품·비즈니스 3축으로 분류
  2. 즉시 반영 가능한 것 vs 장기 과제 분리
  3. 다음 버전(Step 6) 방향성 제안
- **출력**: `runs/harness_demo/피드백정리.md`

### 입력 정의
| 입력 | 형식 | 필수 | 비고 |
|------|------|------|------|
| 검증된 MVP | Python + Claude API | Yes | Step 4 통과 전제 |
| 샘플 카톡 | CSV | Yes | 민감 정보 제거 |
| 시간 | 15~30분 | Yes | 대표 일정 확정 |

### 출력 정의
| 출력 | 형식 | 위치 |
|------|------|------|
| 시연 스크립트 | Markdown | `runs/harness_demo/시연스크립트.md` |
| 시연 결과 | Markdown | `runs/harness_demo/시연결과.md` |
| 피드백 정리 | Markdown | `runs/harness_demo/피드백정리.md` |

### 완료 기준
1. 시연 스크립트 작성 완료
2. 대표에게 1회 이상 시연 완료
3. 피드백 3건 이상 수집
4. 다음 단계 방향성 합의

### 잠재 실패 모드

| 실패 모드 | 징후 | 대응 |
|-----------|------|------|
| 대표 일정 불가 | 미팅 확정 안 됨 | 비동기 데모 영상 제작으로 우회 |
| 라이브 에러 | 시연 중 스크립트 크래시 | 미리 녹화된 결과 + 라이브 시도 병행 |
| 대표 무관심 | "재밌네요"로 끝, 구체적 피드백 없음 | 구체적 질문 3개 준비 ("누가 사겠나?" "무엇이 부족한가?" "비슷한 거 쓰나?") |
| 개인정보 이슈 | 시연 중 민감 정보 노출 | 샘플 카톡은 반드시 사전 익명화 |
| 과도한 기대 | 대표가 즉시 상용화 요구 | "현재 프로토타입, 다음 단계"로 범위 관리 |

4. **대표 카톡 사용 동의** (선택): 라이브 시연 시 대표 본인 카톡 사용 여부

## 의존성

```
Step 1 (리뷰) → Step 2 (MVP 정의) → Step 3 (MVP 구현) → Step 4 (테스트) → Step 5 (시연)

                                                              이상규 동의 필요
```
