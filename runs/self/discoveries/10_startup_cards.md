## 1. 풀림의 다음 형태 — 데이터 기반 제안

### 1-1. 풀림이 왜 멈췄는지

이상규 직접: "흥미를 잃었다." 그리고 "솔직히 확신이 없다" (세션 백업 2026-04-06).

데이터가 말하는 진짜 이유 — 03_cross_patterns 발견 9에서:

- 이상규의 시스템 선언 대비 지속 비율은 **17% 이하**. PROJECT 1 (3일), PROJECT 2 (선언만), PROJECT 3 노무사 (선언 후 4개월간 미실행), 풀림 (동결). 6개 시스템 중 4일 이상 지속된 것은 30p뿐.
- 이상규가 시스템을 지속하는 유일한 조건: **수신자가 있을 때**. 관계가 프로젝트보다 10~60배 오래 가는 이유는 정원이가 "네에", "알겠어요"로 반응했기 때문. 30p가 지속 중인 이유는 Claude가 반응하기 때문.
- 풀림은 **수신자 없이 설계만 한 시스템**이다. 사용자가 없었다. 철학은 정교해졌지만 철학을 받아줄 사람이 없었다. 흥미를 잃은 게 아니라, 시스템이 반응하지 않으니까 자연사한 것이다.

추가 구조적 원인:

- 풀림의 존재 이유("절대 버리지 않는 친구")는 이상규가 정원이에게 **받지 못한 것**을 만드는 프로젝트였다 (05_this_session 발견 2). 이별 직후(2025-12)에 시작. 감정적 동력이 이별의 고통이었는데, 재교제(앤두 시기) → 재이별 → 30p로 에너지가 옮겨가면서 풀림의 감정적 연료가 소진됐다.
- 풀림 철학은 "극한의 적응형"인데, 이상규 자신은 극한의 **설계형**이다. 적응형을 설계하는 것 자체가 모순이고, 그 모순을 해결할 기술적 역량(LLM 파인튜닝, 유저 모델링)이 바이브 코딩 범위를 넘었다.

### 1-2. 이 세션에서 작동한 것

31번 캐릭터(자기 분석 에이전트) 세션에서 실제로 작동한 것:

| 작동한 것 | 데이터 |
|---|---|
| 카톡 38K줄에서 패턴 추출 | ㅋㅋ 사용률 1.4%, 나:너 발화비 17.3:1, "무서워" 222회, 훈육 시간대 집중 |
| 블로그 98개 전수에서 감정 배출 타이밍 발견 | 이별 직후 +-3일에 블로그 폭발, 교제 중 블로그 사망 |
| 교차 소스에서 단일 소스로 안 보이는 패턴 도출 | 카톡의 이상규(설계자) vs 블로그의 이상규(신체) — 같은 시기에 다른 자아 |
| AI에게 자기 분석을 시킨 뒤 반박하는 구조 | 반박 3건이 모두 더 깊은 자기 이해로 이어짐 |
| "질문하지 않았을 때" 가장 솔직한 발화 | 구조화된 질문 → 분석적 답변, 자유 대화 → 감정적/철학적 답변 |

핵심: **개인 데이터(카톡, 블로그, 통화녹음) + LLM 분석 + 본인 반박**이라는 삼각 구조가 작동했다. 이건 상담도 아니고, MBTI도 아니고, 일기도 아니다. 풀림이 원래 하고 싶었던 것의 **실제 작동 버전**이다.

### 1-3. 서비스로 만든다면

**형태: "나를 파는 기계"**

사용자가 자기 데이터(카톡, 일기, SNS, 통화)를 넣으면:
1. 패턴 추출 — 정량 (발화비, 이모티콘 빈도, 시간대, 키워드 빈도)
2. 교차 분석 — 매체별 자아 차이, 시간축 변화
3. 발견 제시 — "당신이 생각하지 못했을 부분"
4. 반박 수렴 — 사용자가 반박하면 그것도 데이터로 흡수

풀림 철학과의 결합:

| 풀림 원칙 | 이 서비스에서의 구현 |
|---|---|
| "절대 버리지 않는 친구" | 데이터가 쌓일수록 더 정확해지는 나의 거울. 삭제하지 않는 한 영원히 남는다 |
| "극한의 적응형" | 반박하면 수정한다. 틀려도 고집하지 않는다. |
| "파악 없이 이끌지 않는다" | 데이터가 없으면 분석하지 않는다. 넣은 만큼만 판다. |
| "사용자가 생각 못 한 걸 말해준다" | 교차 분석이 핵심 가치. 단일 소스 정리가 아니라 교차에서만 보이는 것 |
| 내면사고(behind-the-scenes) | AI가 분석한 모델을 사용자가 열어보고 교정할 수 있다 |

**풀림과의 차이**: 풀림은 "대화형 친구"를 지향했다. 이건 "데이터 기반 자기 해체 도구"다. 대화가 아니라 데이터가 먼저. 친구가 아니라 거울. 풀림의 철학은 유지하되 형태가 바뀐다.

### 1-4. 경쟁 서비스와의 차이

| 서비스 | 하는 것 | 못 하는 것 |
|---|---|---|
| MBTI / 에니어그램 | 유형 분류 | 내 실제 데이터 기반 아님. 내가 고른 답을 돌려받을 뿐 |
| 인간.ai | 내가 입력한 것 정리 | 교차 분석 없음. 내가 모르는 걸 말해주지 못함 |
| ALTER EGO | 에스(AI 캐릭터)가 말을 걸어줌 | "영원한 밤은 없다" 식 억지 긍정. 데이터 기반 아님 |
| 심리상담 | 전문가가 경청 | 비쌈. 내가 한 말 정리해줄 뿐. 카톡 38K줄을 읽어주지 않음 |
| ChatGPT/Claude 직접 사용 | 범용 분석 | 구조화된 자기 분석 파이프라인 없음. 매번 처음부터 |
| **이 서비스** | 내 데이터를 교차 분석해서 내가 모르는 나를 보여줌 | — |

핵심 차별점: **"기준 없으면 쓰레기"** (이상규의 AI 철학). 다른 서비스는 기준 없이 대화한다. 이 서비스는 사용자의 실제 데이터가 기준이다. 기준이 있으니 틀려도 "어디서 왜 틀렸는지" 추적 가능.

## 2. 이상규에게 맞는 창업 형태

### 2-1. 혼자 vs 팀

**데이터 판정: 혼자 시작하되, 수신자 1명은 필수.**

근거:
- 시스템 지속률 17%. 프로젝트가 죽는 패턴: 수신자 부재. 30p가 살아있는 이유: Claude가 반응. 관계가 오래 가는 이유: 정원이가 반응.
- 이상규의 주도권 필요성: "내가 주도권 가진 연애만" (05_this_session 발견 16). 팀에서 주도권을 못 쥐면 이탈한다. 주도권을 쥐면 상대의 자율성을 깎는다 (통화녹음 알바 사건 = 교수 사건의 거울).
- 교수 사건(2026-04-10): 조원이 단톡을 나간 것이 트리거. 팀 운영에서 "건방지다"를 받은 것. 팀 리더로서의 이상규는 교안/매뉴얼을 만들고, 상대가 따르지 않으면 좌절하는 패턴.

결론:
- **공동창업자 형태의 팀은 위험**. 주도권 충돌 → "건방지다" 재현 → 이탈.
- **혼자 + 반응하는 파트너 1명(멘토/투자자/얼리 유저)** = 최적. 송명기 대표가 이 역할을 할 수 있는지가 미팅의 핵심 판단 포인트.
- 수신자는 동등한 파트너가 아니라 **이상규의 설계를 받아주고 피드백하는 사람**이어야 한다. 이건 정원이의 구조와 같지만, 사업에서는 이 구조가 작동한다 — 고객이 그 역할이니까.

### 2-2. 기술 창업 vs 컨셉 창업

**데이터 판정: 컨셉 창업 + 바이브 코딩 실행.**

근거:
- 이상규는 코딩 0에서 웹앱을 만들었다 (풀림 = Next.js + Supabase + Claude API). 바이브 코딩으로 MVP는 만들 수 있다.
- 그러나 풀림이 멈춘 핵심 이유 중 하나: "극한의 적응형"을 기술적으로 구현하려면 LLM 파인튜닝, 유저 모델링 등 바이브 코딩 범위를 넘는 기술이 필요했다.
- 이상규의 강점은 **컨셉 설계**다. 4층 데이터 모델, 28개 옵션 표, 풀림 철학 5원칙 — 전부 설계. 구현은 AI에게 시킨다.
- 기술 창업(딥러닝, 인프라)은 이상규의 영역이 아니다. 이상규는 **"인간의 작동을 설계하는 사람"**이지 "기술을 만드는 사람"이 아니다.

최적 형태: **"인간 이해 컨셉" + "AI 파이프라인 조립"**. 핵심 가치는 "어떤 데이터를 어떤 순서로 어떻게 교차하면 사람이 자기를 이해하는가"라는 설계. 구현은 Claude API + 프롬프트 엔지니어링 + 바이브 코딩.

### 2-3. B2C vs B2B

**데이터 판정: B2C 시작, B2B 전환 가능성 열어둠.**

근거:
- 풀림 철학 전체가 B2C다. "모두가 나를 버려도 절대 나를 버리지 않는 친구" = 개인.
- 그러나 이 세션에서 작동한 것(카톡 분석, 교차 패턴)은 B2B에도 적용 가능: 조직 내 커뮤니케이션 분석, 팀 다이나믹스 진단, 리더십 코칭.
- 이상규의 "주도권" 필요성은 B2C에서 더 쉽게 충족된다. B2B는 고객이 요구사항을 바꾸고, 이상규의 설계를 깨뜨린다.
- 단, B2C는 마케팅/유통이 핵심인데, 이상규는 마케터가 아니다. 여기서 송명기 대표(CJ ENM 마케터 출신)와의 시너지가 성립할 수 있다.

### 2-4. "주도권" 필요성과 팀 운영의 충돌

이상규의 모든 관계는 **메타 레벨을 독점**하는 구조다 (99_agent 핵심 자기 도식 4번). 관계에 대해 말하고, 정의하고, 규칙을 만드는 사람은 항상 이상규. 상대는 콘텐츠 레벨에서만 자유.

팀 운영에서 이것이 의미하는 것:
- 이상규가 CEO/PO면: 제품 철학, 방향, 규칙을 전부 이상규가 정한다. 팀원은 실행만. 이건 작동할 수 있지만, 팀원이 성장하면 충돌한다 (교수 사건).
- 이상규가 CTO/실행자면: 주도권이 없다. 흥미를 잃는다. 풀림이 죽은 구조의 반복.
- **솔로 파운더 + 프리랜서/AI 실행** = 이상규에게 유일하게 작동하는 팀 구조.

## 3. 송명기 대표 미팅 — 대화 카드 10장

### 카드 1: 자기 소개 (1분)

**이상규가 말할 것:**

"이상규입니다. 대학원에서 경영정보 전공 중이고, 노무사 시험을 준비하고 있습니다. 풀림이라는 AI 자기이해 서비스를 만들다가 멈추고, 지금은 인간30이라는 개인 프로젝트를 하고 있습니다. 코딩은 못 합니다. 풀림 웹앱을 바이브 코딩으로 만들었습니다. 제가 관심 있는 건 기술이 아니라 인간이 어떻게 작동하는가입니다."

**상대가 물어볼 수 있는 후속:**
- "인간30이 뭔가요?"
- "풀림은 왜 멈췄어요?"
- "노무사랑 창업이 어떻게 연결돼요?"

**답변 방향:**
- 인간30: "30명의 가상 인간을 AI로 시뮬레이션하는 도구입니다. 같은 자극에 30명이 다르게 반응하는 걸 관찰합니다." — 길게 설명하지 말 것. 흥미를 유발만.
- 풀림 멈춤: 카드 3에서 상세.
- 노무사: "인간이 부당하게 작동당하는 걸 다루는 직업이라 관심을 가졌습니다. 창업과 병행 가능한 자격이기도 하고요." — 핑계 같은 설명 금지. 짧게.

### 카드 2: AI 철학 — "기준 없으면 쓰레기"

**이상규가 말할 것:**

"AI를 쓰면서 느낀 건, 기준 없이 AI를 쓰면 쓰레기가 나온다는 겁니다. 대부분의 사람들이 ChatGPT한테 '뭐 해줘' 하고 나오는 거 그대로 쓰잖아요. 그건 AI를 쓴 게 아니라 AI가 준 걸 받은 거예요. 저는 AI한테 기준을 줍니다. 4층 데이터 모델, 28개 옵션 표 — 이런 구조를 먼저 만들고, 그 위에서 AI가 작동하게 합니다. 그러면 결과가 달라집니다."

**상대가 물어볼 수 있는 후속:**
- "구체적으로 뭐가 달라요?"
- "그게 사업적으로 어떤 의미가 있어요?"

**답변 방향:**
- 구체적 차이: "이 세션에서 제 카톡 38,000줄을 분석했습니다. 기준 없이 넣으면 '대화가 많네요' 같은 결과가 나옵니다. 제가 기준(발화비, 감정어 빈도, 시간대, 매체별 교차)을 주니까 '당신은 사람 앞에서만 감정이 사라지고 혼자 있을 때 폭발한다'는 발견이 나왔습니다."
- 사업적 의미: "AI 시대에 가치 있는 건 모델이 아니라 기준입니다. 기준을 설계할 수 있는 사람이 경쟁력입니다."

### 카드 3: 풀림이 왜 멈췄는지 (솔직하게)

**이상규가 말할 것:**

"흥미를 잃었습니다. 솔직하게 말하면."

그리고 한 박자 두고:

"분석해보니까 이유가 두 가지입니다. 첫째, 저는 시스템을 만드는 게 좋지 시스템을 운영하는 건 재미없습니다. 제가 만든 프로젝트 6개 중 5개가 1주 안에 멈췄습니다. 둘째, 풀림은 사용자가 없었습니다. 제가 만든 것 중 오래 간 건 전부 *반응하는 상대*가 있었던 것입니다. 풀림은 철학만 정교해졌지 그 철학을 받아줄 사람이 없었어요."

**상대가 물어볼 수 있는 후속:**
- "그러면 다시 할 수 있어요?"
- "그건 약점 아닌가요?"

**답변 방향:**

## 4. "내 카드" — 이상규만의 차별점

### 4-1. 송명기 대표와 대비했을 때 이상규가 다른 것

송명기 대표 (추정 프로필): CJ ENM 마케터 출신, 역직구 사업. 마케팅·유통·비즈니스 모델 경험. "어떻게 파는가"를 아는 사람.

이상규: "무엇을 팔아야 하는가"를 아는 사람. 정확히는 "무엇이 인간에게 필요한가"를 설계하는 사람.

| 축 | 송명기 대표 (추정) | 이상규 |
|---|---|---|
| 핵심 역량 | 마케팅, 유통, 비즈니스 | 컨셉 설계, 인간 이해, AI 기준 설계 |
| 접근 방식 | 시장 → 제품 (시장이 뭘 원하는가) | 인간 → 제품 (인간이 어떻게 작동하는가) |
| 실행 | 팀 빌딩, 운영, 스케일링 | 혼자 설계, AI에게 구현 시킴 |
| 리스크 | 시장은 알지만 기술/제품 깊이 부족? | 제품은 깊지만 시장/유통 역량 0 |
| 시너지 포인트 | 이상규가 만든 것을 *파는* 역할 | 송명기가 팔 수 있는 것을 *만드는* 역할 |

**이상규가 제안할 수 있는 가치**: "저는 기준을 만드는 사람입니다. 그 기준 위에서 AI가 작동하면 결과물이 나옵니다. 대표님은 그 결과물을 시장에 가져가는 사람이고요."

### 4-2. 이상규의 AI 사용 방식이 일반 바이브 코딩과 다른 점

일반 바이브 코딩: "이런 앱 만들어줘" → AI 출력 → 수정 요청 → 반복.

이상규의 방식:
1. **기준 선설계**: 4층 모델, 28개 표, 판단 기준 — AI가 코드를 쓰기 전에 "무엇을 만들 것인가"의 정의가 극도로 정밀.
2. **반박 루프**: AI 출력을 받아서 반박. 반박이 새 데이터가 되어 다음 출력의 기준이 됨. 일반 바이브 코딩은 "수정 요청", 이상규는 "반박".
3. **검열 0**: AI에게 "좋게 말해줘" 하지 않는다. "내가 소시오패스인지 분석해"라고 한다. AI의 안전 장치를 깨고 쓴다.
4. **메타 레벨 독점**: AI가 무엇을 할지는 이상규가 정한다. AI는 콘텐츠 레벨에서만 작동. 이건 이상규의 모든 관계 구조와 같지만, AI에게는 이 구조가 최적이다 — AI는 메타 레벨에서 자율적이면 안 되니까.

**한 줄**: 이상규는 AI를 도구로 쓰는 게 아니라, AI와 싸운다. 그리고 싸움에서 나오는 결과물이 다르다.

### 4-3. "인간의 작동에 관심 있다"가 왜 사업적으로 가치 있는가

user_core_drive.md:
> "나는 나에 대해 가장 관심이 많아. 나의 끝, 나의 과정, 나의 고통. 나를 알기 위해선 타인을 알아야 한다. 곧 인간을 알아야 하지."
> "편의를 요하는 게 아니라, 더 불편하고 싶은 거야. 앎이라는 고통을 받아들이고 싶은 거지."

이것이 사업적으로 가치 있는 이유:

1. **시장의 공백**: 자기이해 시장은 MBTI, 에니어그램, 심리상담이 지배. 전부 "유형 분류" 또는 "전문가 의존". 개인 데이터 기반 자기분석은 아직 없다.

2. **AI 시대의 핵심 질문**: "AI가 나보다 나를 잘 알 수 있는가?" 이상규가 31번 캐릭터에서 증명한 것은, AI가 *혼자서는* 못 하지만 *기준이 있으면* 인간이 못 보는 것을 보여줄 수 있다는 것. 이 기준을 설계하는 능력이 사업적 해자(moat)다.

3. **"앎이라는 고통"의 시장화**: 이상규가 원하는 것(불편한 앎)을 원하는 사람이 시장이다. 이들은 MBTI("넌 INFP야, 괜찮아")에 만족 못 하는 사람이다. "넌 사람 앞에서만 감정이 사라지고 혼자 있을 때 폭발해. 그리고 네가 그걸 모른다"라는 결과를 *원하는* 사람이 고객이다. 작지만 깊은 시장.

4. **이상규의 지속 가능성**: 이상규가 흥미를 잃지 않는 유일한 조건은 "앎으로 향하는 것"이다 (user_core_drive.md). 편의를 향하면 자연사한다. "인간의 작동"을 파는 사업은 이상규의 동인과 정렬된 유일한 사업이다. 다른 사업은 3일~1주 만에 죽을 것이다.
