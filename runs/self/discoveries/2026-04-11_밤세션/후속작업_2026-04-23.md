2. **30p 다음 실험 후보 (a) "진짜 타인 1차 데이터 입력"을 먼저 실행할지** — 오퍼스 핵심 권고. 이 실험이 발견 축을 충분히 주면 자극엔진 불필요.

5. **프로토타입 "놀랐다" 판정 방식** — 즉시 이진판정(소넷) vs 24시간 후 재판정 추가(오퍼스). "맞다" ≠ 성공, "놀랐다" = 성공의 경계를 본인이 어떻게 느끼는지.

## 후속 작업 10개 (우선순위 순)

### 1. [결정대기] 30p 후보(a) 실험 vs 자극엔진 착수 — 이상규 판단

오퍼스 반대판정의 핵심: "30p 안의 다음 실험 후보 (a)를 먼저 실험해서 결과를 본 후에 자극엔진을 짓는지 결정하라." 이것이 최우선. 상규가 (a)를 먼저 하겠다 → 자극엔진 착수 보류. (a) 안 하겠다 → 자극엔진 착수 검토 개시.

**전제**: 30p 4/30 데드라인 이후. 착수 전 72시간 냉각.

### 2. [선행] 고고학자 Step4-5 실행

HARNESS Step4-5 스펙은 SELF-2에서 완성(~/pp/30p/runs/self/HARNESS_Step4-5_스펙_2026-04-24.md). 실제 실행. 완료 후 "발견 충족/부족" 판정이 자극엔진 착수 정당성의 전제.

### 3. 프로토타입 입력 텍스트 접근성 확인

소넷이 "합리적 가정"으로 남긴 runs/self/ 내 카톡 원문·일기 원본 실제 존재 여부 확인. NEXT_v2 "실시간 패턴" 섹션도 실제 파일에서 읽을 수 있는지. 프로토타입 실행의 전제.

### 4. 외부 서사 DB 초안 큐레이션 (오퍼스 원칙 적용)

소넷 15개 후보를 오퍼스 기준(상규 취향 20% 상한, 비취향 40% 하한)으로 재검. Claude가 "상규가 싫어할 만한 50개 텍스트"를 먼저 제안 → 상규 거부권만 행사. 장르·시대·지역 쿼터 하드락 적용. 초기 50개 목표.

### 5. STEP 1-3 프롬프트 초안 작성

소넷 의사코드(구조추출→DB매칭→재기술) 기반으로 실제 프롬프트 파일 작성. 오퍼스 3단 필터(인용가능성/반복교차/역방향설명)를 STEP 2-3에 통합. "공명" 금지어 패치 적용. 출력은 항상 "재료"이지 "결론"이 아님을 시스템 프롬프트에 박기.

### 6. 거울 트랩 방어 설계 통합 문서

오퍼스 3경로(취향수렴/자료과잉/불편=진짜) + 각 방어책(A/B/C)을 단일 설계 문서로 통합. DB 구축 원칙·판정 프로토콜·피로 게이트를 한 곳에. 착수 시 체크리스트 8개(오퍼스 "그럼에도 만든다면 조건")도 여기에 포함.

### 7. 착수/폐기 판정 기준 문서

프로토타입 3회 실행 후 판정 기준 명문화. 소넷 기준(1회 놀람=성공) + 오퍼스 기준(3회 중 2회 재포장=폐기) 통합. "놀람" vs "맞음" 구별 가이드("그렇지 그래"=실패, 즉각 불편/낯섦=성공). 24시간 후 재판정 프로토콜 포함.

### 8. 정당화 4층 감시 체크리스트

NEXT_v2에서 관찰된 정당화 4층("이번엔 다르다"·"누군가에게 도움"·"이건 다른 구멍이다"·"지금 안 하면 영원히 안 한다")의 재발 감지 항목. 자극엔진 작업 중 이 항목 중 2개 이상 동시 등장 시 작업 일시정지. 풀림 재실패 경로 조기 차단.

### 9. 4/30 이후 타임라인 초안

30p 데드라인 이후 자극엔진 관련 일정. 72시간 냉각 → (a) 실험 결과 확인 → 고고학자 판정 → 자극엔진 착수/폐기 결정 → 착수 시 프로토타입 1회(주 1) → 판정 → 2회 → 판정 → 3회 → 최종 판정. 예상 기간: 5/1~5/31.

### 10. [선행] 30p 후보(a) 실험 프로토콜

"진짜 타인 1차 데이터 입력" 실험 설계. 30p 캐릭터 30명에게 상규 자료가 아닌 타인의 실제 1차 데이터를 입력으로 주어, 그 반응에서 "발견" 축이 생성되는지 관찰. 성공 시 자극엔진 필요성 하락, 실패 시 자극엔진 정당화 상승.
