## 1. 오늘 밤의 정체성 세 줄

| 층 | 문장 |
|---|---|
| **north star** | AI는 새로운 도구로 삶을 어떻게 바꾸고, 인간을 어떻게 더 탐구할까. |
| **역할** | 나는 **삶의 평론가**다. 도메인은 표면이고 주제는 삶 하나다. |
| **도구관** | AI는 타인이 아니라 **외주 뇌**다. |

한 줄 녹임: **"AI를 외주 뇌로 쓰는 삶의 평론가."**

### 출처 추적 (이 세 줄이 어떻게 만들어졌나)

- **north star**: 상규의 직접 문장 — *"AI는 새로운 도구로 삶을 어떻게 바꿀까, 인간을 어떻게 더 탐구할까, 이런 게 좀 있어."*
- **역할 (평론가)**: 상규의 자기 관심 리스트(영화·만화·책·대화·토론·건강·사람 평가)와 회피 리스트(여행·술자리·다인 모임)를 합친 결과. 모든 좋아하는 대상이 "평가 가능한 텍스트"였고, 무리 안보다 무리 바깥에서 관찰하는 걸 선호. 인류학자(중립 관찰)가 아니라 평론가(시각을 가진 평가)가 정확.
- **도구관 (외주 뇌)**: 상규 직접 문장 — *"타인이라고 느껴지진 않고 내 뇌를 외주화하는 느낌. 미니뇌."* 초기엔 "미니뇌"였고, 상규가 타자성 잔여를 잘라내며 "외주화"로 정정. 외주 프레임은 **평가 권한이 발주자(상규)에게 자동으로 있음**을 전제 — 평론가 체질과 정합.

## 2. 나다움 공식 (상규 직접 발언의 형식화)

> **나다움 = 기존 나 × 새로움**
>
> (a) 새로운 것에서 나를 발견
> (b) 이미 있는 나에서 새로움을 발견
>
> 두 축의 **곱**. 한쪽만 있으면 거울, 둘 다면 창문.

### 출처

상규의 직접 문장: *"나다우는 것은 나를 바깥에서 발견하거나 내가 바깥을 볼 수 있게 해주거나, 그러니까 정확히 말하면 바깥이라는 건 새로운 거고. 새로운 거에서 나를 발견하거나 이미 있는 나에서 새로움을 발견해주거나."*

### 왜 곱인가 (한쪽만으로는 부족한 이유)

- **기존 나만**: 거울. 자기 메아리. 상규 직접 지적 — 풀림이 이 구조였고, "나 만들기"가 이 구조였고, 오늘 낮 31번 에이전트 v1이 이 구조.
- **새로움만**: 무관. 외부 정보가 상규와 접점 없음. 검색 결과, 랜덤 기사, 취향 무시 추천.
- **곱**: 창문. 새로움이 기존 나를 통해 굴절되어 들어오고, 기존 나가 새로움을 통해 다르게 보인다.

## 4. 31번 에이전트 v1 실패의 구조적 재진단

`NEXT_v2.md`가 기록한 v1 실패("내가 아닌데" 5건, "뻔해" 3건, "몰랐는데" 1~2건)의 **구조적 원인**:

### 요구된 모드가 구조적으로 불가능했음

v1은 **"이 사람이 돼라"** 프레임이었다. 이건 AI한테 **타인**이 되라는 요구. AI는 타인이 될 수 없다 — 실존적으로 변하지 않는 존재이기 때문. 이 한계는 상규 본인이 `feedback_persuasion_contract.md`에 직접 써둔 것이다:

> "AI는 경험으로 성장하지 않음. 피드백으로 바뀌는 건 템플릿 업데이트이지 실존적 변화가 아님."

즉 v1의 요구와 상규 자신이 써둔 한계가 모순. 실패는 기술 부족이 아니라 **설계 모순**.

### 올바른 프레임은 "외주 뇌"

- AI에게 타인을 요구하지 말 것.
- AI를 **뇌 외주 부서**로 쓸 것: 상규의 자료 처리·매칭·비교·추출·라벨링·번역 담당.
- 판단·시각·평가는 상규가.
- 평론가 체질과 정합.

### v2 설계 원칙 (이 파일이 v2 착수 전 제안)

1. **"상규 재현" 목표 삭제.** 복제는 거울 트랩.
2. **"상규가 못 보는 것을 드러내는 외주 뇌" 목표 유지·강화.** NEXT_v2가 이미 도달한 방향.
3. **평론가 포맷으로 재작성**: v2 출력은 "이 사람이 이렇게 말했다" 흉내가 아니라 "이 자료에서 이런 구조가 보인다 / 이 패턴이 자주 반복된다 / 이 지점에서 자기 해석과 실제 행동이 갈라진다" 같은 **분석 리포트** 형식.
4. **입력에 (a)축 추가**: 상규 본인 자료만 넣지 말고 **외부 원형**(문학·신화·다른 삶의 원본 기록·30p 캐릭터 해석)을 교차 입력.

- 풀림은 구조적 실패 제품이었음 확정.
- 풀림 UX 자산(사다리형 결정 지원, 선택지 상황 가정 UX 등)은 **살림**. 필요 시 다른 트랙으로 이식 가능.

### 구조적 실패 이유 (기록 목적)

1. **거울 구조**. 사용자 고민 입력 → 고민 정리 출력. (a)축 없음. 사용자가 이미 아는 것을 다른 형태로 돌려줌. 새로움 없음 → 손 안 감.
2. **타인 흉내 요구**. 풀림은 "힘들 때 옆에 있어주는 친구"를 제공하려 했음 = AI에게 타인이 되라는 요구 = 오늘 낮 31번 v1 실패와 동일 구조 = AI 본질 위반.
3. **카톡 고고학자 프로젝트(HARNESS_product)가 풀림의 실제 후계자**. 풀림의 UX 일부(반박 루프, 심층 질문)가 이미 그쪽으로 이식돼 있음. 집착 내려놓기가 곧 포기가 아니라 **자리 옮김**임을 이 사실이 입증한다.

## 6. 외주 원칙 — 평론가 전용
