## 한 문장 정의

사용자 기록의 반복 구조를 추출해 외부 서사 원형과 매칭함으로써, 본인은 알아채지 못한 삶의 패턴을 낯선 문장으로 되돌려주는 발견 엔진.

---

## 타깃 페르소나 (구체 1명)

**이상규 본인이 1번 유저.** 이유: 자극 엔진의 가치는 "맞다" 반응이 아니라 "놀랐다" 반응으로만 검증 가능하다. 놀람 판정을 할 수 있는 사람이 개발 초기에는 상규뿐이다. 1번 유저로 돌아가봐야 "어떤 구조에서 놀람이 발생하는가"를 빠르게 학습할 수 있다.

**2번 유저 후보**: 자기 기록(일기·메모·대화)을 오래 쌓아왔지만 그 기록을 분석하는 도구가 없어서 쌓기만 한 사람. 자기 이해에 관심이 있되, 심리 상담 서사(공감·치유·수용)를 불편하게 여기는 사람. 상규와 유사한 체질 — 평론가형, 분석 자체를 지적 즐거움으로 취급하는 유형.

## 차별점 (고고학자 / 풀림 / 30p 대비)

### vs 고고학자 (HARNESS_product)

| 항목 | 고고학자 | 자극 엔진 |
|---|---|---|
| **입력 공간** | 상규 기록 단독 (카톡 53K줄, 블로그, 일기) | 상규 기록 + 외부 서사 원형 (문학·신화·영화) |
| **처리 방향** | 내부 패턴 추출, 시계열 분석, 통계 | 내부 구조 × 외부 서사 구조 교차 매칭 |
| **출력 성격** | "이런 패턴이 당신 기록에 반복된다" | "당신 기록의 이 구조가 이 서사와 같은 형태다" |
| **나다움 공식** | (b)축 전담 — 이미 있는 나에서 새로움 발견 | (a)×(b) 곱 — 외부 서사로 기존 나를 비추고, 기존 나로 외부 서사를 굴절 |
| **MVP 완성도** | MVP+PWA 완료, Step 4-5 대기 상태 | 설계 단계 |
| **공존 방식** | 자기 데이터의 통계·언어 변화 찾기 원할 때 | 낯선 문장으로 충격 원할 때 |

둘은 같은 사용자가 번갈아 쓸 수 있다. 고고학자를 통해 패턴을 발견하고, 그 패턴을 자극 엔진에 던지면 외부 서사 비교가 되돌아온다. 반대도 가능 — 자극 엔진에서 나온 매칭 결과를 고고학자에 넣어 해당 패턴의 실제 데이터를 확인. 순서 없는 왕복 구조.

UX 자산 공유 가능: 반박 루프, 심층 질문 생성 모듈. 단 고고학자의 Step 4-5 경로(대화 인터페이스, PWA)는 자극 엔진이 동일하게 쓸 수 있다.

### vs 풀림

풀림은 "힘들 때 옆에 있어주기" — AI에게 타인 역할을 요구하는 구조였고, 그 구조가 실패 원인이었다. 자극 엔진은 정서 파트너를 목표로 하지 않는다. 사용 시점이 다르다: 심심할 때·막힐 때·뇌가 멈춰 자극이 필요할 때. 치유가 아니라 발화(ignition).

### vs 30p

30p는 타인 30명이 같은 자극에 어떻게 다르게 반응하는지 관찰하는 도구다. 자극 엔진은 상규 1명의 기록이 외부 서사의 어떤 구조와 겹치는지를 보는 도구다. 관찰 대상이 다르다 — 30p는 타인들, 자극 엔진은 상규 본인.

## 외주 뇌 사용 방식

사용자가 외주하는 것: **구조 추출 + 매칭 + 낯설게 하기 번역**

- 사용자 기록에서 반복 구조 찾기 (결정 루프, 회피 패턴, 관계 형식)
- 그 구조와 겹치는 외부 서사 찾기
- 그 서사의 언어로 구조를 기술하기

사용자가 외주하지 않는 것: **매칭이 정확한지 판단, 어떤 느낌인지, 이게 의미하는 게 무엇인지**

이게 핵심이다. 자극 엔진은 판정을 사용자에게 돌려보낸다. 출력은 항상 재료이지 결론이 아니다. "당신의 결정 루프가 뫼르소 구조와 같습니다"는 사실 제시다. "그러니 이렇게 하세요"가 붙는 순간 외주 뇌가 아니라 상담사가 된다.

## MVP 기능 (3-5개, 우선순위)

**1순위: 구조 추출 → 매칭 → 원문 인용 출력**

입력: 상규의 텍스트 조각(일기 1회차, 메모, 대화 요약). 출력: 이 기록에서 추출된 구조 + 매칭된 외부 서사 + 그 서사의 실제 문장(원문 인용). 클릭 없이 실행되는 단일 API 호출로.

**2순위: 구조 뱅크 축적**

처음엔 LLM이 그때그때 추출하지만, 반복 실행 후 "이 사람에게 자주 등장하는 구조 5개"가 축적된다. 뱅크가 쌓일수록 매칭 정밀도가 올라간다.

**3순위: 낯선 서사로 재기술**

추출된 구조를 그 서사의 어휘로 다시 쓴다. 예: "당신이 결정을 미루는 루프"를 "뫼르소가 어머니 죽음 앞에서 감정을 검열한 것과 같은 구조"로 재기술. 핵심은 다른 어휘로 오게 만드는 것.

**4순위: 반박 루프**

사용자가 "이건 아닌 것 같다"고 말할 수 있다. 엔진이 반박에 대응: 왜 그 매칭을 선택했는지 근거 제시, 혹은 다른 서사로 교체. 반박이 정보가 된다 — 어디서 저항이 생기는지가 오히려 데이터.

**5순위: 콜드 스타트 모드**

기록이 없는 상태에서 시작하는 사람을 위한 입력 세션. 3-5개 질문으로 현재 상태 스냅샷 수집, 그것으로 첫 매칭 시도. 정밀도는 낮지만 진입 장벽 제거.

## 첫 2주 실험 (상규 본인 프로토타입 1회 실행)

**목표**: 상규 데이터 1개로 매칭 1회 실행, "놀랐다"가 나오는지 확인.

**측정 기준**: 이진 판정 — 상규가 읽고 "놀랐다"고 말하거나 말하지 않거나. 점수 없음, 정성 없음. "놀랐다" 1건이면 실험 성공. 0건이면 프롬프트 수정 후 재실행.

## 위험 (3개, 각 대응안)

**위험 1: 매칭이 별자리 운세 수준이 될 가능성**

모든 사람에게 "당신은 시시포스 구조입니다"가 되면 무의미. 보편적 원형이 오히려 놀람을 죽인다.

대응: 매칭 기준을 "구조의 구체성"으로 설정. 일반 패턴(결정 회피)이 아니라 상규 기록에서만 관찰되는 특수 구조(예: "결정 전 정당화 4층 쌓기, 마지막 층이 항상 타인으로 확장")와 매칭할 것. 구조 기술이 구체할수록 운세에서 멀어진다.

**위험 2: 자기 기록 입력에 방어기제가 작동**

사용자가 "보여주기 좋은" 기록만 입력할 경우, 외주 뇌는 세탁된 자료만 처리하게 된다.

대응: 입력 레이어에서 "편집하지 않은" 텍스트 원본을 우선하도록 설계. 일기가 아니라 카톡 원문, 블로그 초안, 삭제된 메모를 우선 입력 소스로. 가공 텍스트는 낮은 가중치.

**위험 3: 서사 DB가 서구 문학 편향으로 굳어지는 것**

초기 큐레이션이 카뮈·헉슬리·장자 같은 고전에 쏠리면, 매칭이 항상 같은 어휘군을 반복하게 된다.

대응: DB를 확장 가능한 구조로 설계 — 작품 추가가 쉬운 포맷(작품명·구조 라벨·원문 인용·적용 조건). 초기는 10개에서 시작해도 구조가 모듈식이면 50개로 확장 시 재설계 없이 가능.

## 나다움 공식 정합 ((a)(b) 축 입력점)

| 축 | 자극 엔진에서의 입력점 |
|---|---|
| **(a) 새로운 것에서 나를 발견** | 외부 서사(카뮈, 장자, 어슐러 르귄 등)가 낯선 언어로 상규 구조를 기술할 때. 상규가 한 번도 자기 자신에게 적용해보지 않은 어휘·원형이 매칭 결과로 오는 것. |
| **(b) 이미 있는 나에서 새로움을 발견** | 상규 기록에서 추출된 반복 구조가 본인이 인식하지 못했던 것일 때. "이 결정 루프가 3년 동안 같은 형태였다"는 식의 발견. |
| **곱** | (a) 외부 서사의 어휘 + (b) 상규 기록의 구조가 만나서 "이 서사가 내 것이었구나"가 생성되는 지점. 둘 중 하나만 있으면 운세이거나 일기 정리이거나 둘 중 하나다. |

## 30p 통합 경로 판단 — 옵션 I vs II + 권장안

### 옵션 I — 독립 제품 (외부 서사 DB 별도 구축)

**설명**: 문학·영화·신화에서 구조를 추출한 텍스트 DB를 30p 외부에 별도로 만든다. 사용자 기록과 매칭. 30p와 무관하게 자립.

**장점**:
- 서사 DB가 30p 캐릭터 설정에 구속되지 않음. 어떤 원형이든 넣을 수 있다.
- 상규 본인 데이터 외에 다른 사용자가 붙었을 때도 30p 없이 작동 가능.
- 타깃이 명확 — 자기 기록 있는 사람 전반.
- 고고학자와 명확히 다른 제품으로 분리됨. 두 제품 사이에 혼동 없음.

**단점**:
- 서사 DB를 처음부터 구축해야 한다. 초기 큐레이션 비용.
- 30p 인프라(4층 28표, seed 생성 스크립트 등)를 재활용할 접점이 없다.
- 4월 데드라인 동안 30p 작업과 병렬 진행 시 주의력 분산.

### 옵션 II — 30p 내부 실험으로 수렴 (30명이 외부 시각 담당)

**설명**: 30p의 30명 캐릭터를 "외부 시각 제공자"로 전용한다. 상규 자료를 30명이 각자 해석 — 캐릭터별로 다른 프레임으로 상규 기록을 읽고, 30개의 비상규적 해석을 돌려준다.

**장점**:
- 30p 인프라를 즉시 재활용. 새 인프라 구축 없음.
- 30p의 "복수성 자체가 흥미" 원칙과 정합. 30개의 다른 어휘·관점에서 나오는 매칭이 단일 외부 서사보다 밀도 높을 수 있다.
- 30p 다음 실험 후보 (a) "상규가 예측 못 한 입력"과 직결 — 30명이 "타인 시각"을 담당하는 구조가 된다.
- 4월 데드라인 안에 30p 작업의 일부로 처리 가능.

**단점**:
- 30명 캐릭터도 결국 상규가 설계한 옵션 표에서 나온 존재. 00_원칙.md의 "거울 트랩" 진단 — "입력이 상규 본인의 발화 스크립트 하나라 30명은 타인이 아니라 상규가 이미 내장한 패턴 30개의 재생"이 그대로 적용될 수 있다.
- 30명이 문학 원형보다 더 얕은 어휘를 제공할 가능성. 캐릭터는 "20세 한국인 시뮬레이터"이지 보르헤스나 장자가 아니다.
- 자극 엔진의 핵심인 "낯선 어휘로 재기술"이 30명 캐릭터로는 제한된다. 상규의 삶을 30세 공대생 관점에서 해석하면 놀람보다 낯섦이 더 많을 것이다.

### 권장안 — 옵션 I, 단 빠른 프로토타입에 옵션 II 부분 차용

**왜 옵션 I인가**: 자극 엔진의 작동 원리는 "낯선 어휘로 재기술"이다. 낯섦은 원형의 어휘 밀도에서 온다. 30명 캐릭터의 어휘는 30p의 4층 28표에서 굴러나온 것들이라 상규가 이미 설계한 어휘 집합 안에 있다. 뫼르소나 장자의 언어는 상규가 설계하지 않은 외부 어휘다. 놀람 생성력이 다르다.

**단 단기 프로토타입에서 옵션 II 차용 가능**: 서사 DB 구축 전, 빠른 1회 실행 테스트를 위해 30명 중 3-5명의 관점으로 상규 기록 해석을 먼저 돌려볼 수 있다. 판단 기준: "이 결과가 놀람을 주는가." 놀람 없으면 옵션 I로 이동이 확인된 것이다.

**4월 데드라인 고려**: 4월은 30p 완성에 집중. 자극 엔진 옵션 I 전체 구축은 5월 이후. 4월 내에 할 것은 (1) 상규 본인 데이터 프로토타입 1회 실행 (옵션 II 차용), (2) 서사 DB 초안 큐레이션(본 문서 섹션에 포함). 실제 매칭 엔진 개발은 5월.

## 초기 큐레이션 텍스트 DB 후보 (10개 이상)

각 작품이 제공하는 구조를 한 줄로. "구조"는 인간 행동 패턴의 형식이지 작품 요약이 아님.

| # | 작품·출처 | 제공하는 구조 |
|---|---|---|
| 1 | 카뮈, 이방인 (뫼르소) | 결정 유예 구조 — 감정 반응을 검열하며 판단을 미루다 외부 사건(총 발사)이 결정을 대신 내리는 형태 |
| 2 | 헉슬리, 멋진 신세계 | 쾌락 과잉 자기 상실 구조 — 불쾌를 제거할수록 자기가 사라지고 쾌락이 자기를 채우는 대체 구조 |

## 구조 매칭 알고리즘 개요 (LLM 의사코드)

### 전체 흐름

```
사용자 텍스트 입력
    → [STEP 1] 구조 추출 프롬프트
    → 구조 라벨 + 행동 패턴 기술
    → [STEP 2] DB 매칭 프롬프트
    → 후보 서사 1-3개 + 매칭 근거
    → [STEP 3] 재기술 프롬프트
    → 해당 서사 언어로 사용자 구조 재기술
    → 출력: 재기술 텍스트 + 원문 인용 + 매칭 근거
```

### STEP 1 — 구조 추출 프롬프트 (의사코드)

```
SYSTEM:
너는 텍스트에서 행동 구조를 추출하는 분석 모듈이다.
감정이나 내용을 요약하지 않는다.
오직 패턴의 형식(결정이 어떻게 내려지는가, 반복이 어떤 형태인가, 
회피가 어떤 구조로 작동하는가)만 추출한다.
출력 형식:
- 결정 루프 구조: [있음/없음, 있다면 어떤 형태]
- 관계 형식: [어떤 역할이 어떻게 배치되는가]
- 감정 주기: [감정이 언제 등장하고 언제 사라지는가]
- 주장 패턴: [논리 전개 방식]
- 회피 지점: [어디서 멈추거나 우회하는가]
각 항목은 1-2문장 기술. 없는 항목은 "없음"으로.

USER:
다음 텍스트에서 행동 구조를 추출하라:
[사용자 입력 텍스트]
```

### STEP 2 — DB 매칭 프롬프트 (의사코드)

```
SYSTEM:
아래는 외부 서사 DB다. 각 항목은 [작품·저자] / [구조 라벨] / [인용문]으로 구성된다.
[DB 전체 또는 요약 삽입]

주어진 사용자 구조와 가장 형식이 유사한 서사를 1-3개 선택하라.
매칭 기준: 형식의 유사성(내용 유사성 아님). 
"이 사람이 이 작품을 좋아할 것 같다"는 취향 추천이 아니라
"이 사람의 행동 패턴이 이 서사의 구조와 같은 형태다"가 기준.
부합하는 서사가 없으면 "없음"으로 반환.

USER:
사용자 구조:
[STEP 1 출력]

매칭 서사를 선택하고, 각각에 대해:
- 어느 구조 항목이 일치하는가
- 왜 이 서사를 선택했는가 (1-2문장)
를 제시하라.
```

### STEP 3 — 재기술 프롬프트 (의사코드)

```
SYSTEM:
너는 사용자 기록의 구조를 외부 서사의 언어로 재기술하는 번역 모듈이다.
사용자에 대한 판단·평가·조언을 덧붙이지 않는다.
"이렇게 하세요"나 "이런 패턴은 문제입니다"를 쓰지 않는다.
기술(description)만. 건조하게.

USER:
사용자 구조: [STEP 1 출력]
매칭 서사: [서사명] / 구조 설명: [STEP 2 출력] / 인용문: [DB 인용]

이 서사의 언어와 원문 인용을 활용해 사용자 구조를 재기술하라.
최대 3문장. 인용문 포함.
```

### 회피 지점 감지 보조 프롬프트 (선택 실행)

```
USER:
위 재기술을 보고 반박하거나 "이건 아닌 것 같다"고 느끼는 부분이 있는가?
있다면 어느 부분인가.

SYSTEM:
사용자가 저항하는 지점을 기록하라.
저항 자체가 데이터다 — 어느 매칭에서 저항이 생기는지가
다음 매칭을 정밀화하는 입력이 된다.
반박이 맞으면 매칭 수정, 반박 자체가 흥미로우면 그 지점에 대한 추가 질문 생성.
```

### 처리 — 어떤 프롬프트

위 "구조 매칭 알고리즘 개요"의 STEP 1 → STEP 2 → STEP 3 순서 그대로 실행.

- STEP 1 입력: 위 선택 텍스트 (가공 없이 원문)
- STEP 2 DB: 본 문서 "초기 큐레이션 텍스트 DB 후보" 15개 사용
- STEP 3 출력: 3문장 이내, 인용 포함, 건조체

### 출력 — 어떤 포맷

```
[구조 추출]
- 결정 루프: ...
- 관계 형식: ...
- 감정 주기: ...
- 주장 패턴: ...
- 회피 지점: ...

[매칭 서사]
- 1순위: [작품명] / 매칭 구조: [어느 항목이 왜]
- 2순위: [작품명] / ...

[재기술]
[3문장 이내, 해당 서사 언어로, 원문 인용 포함]

[판정 입력]
이 재기술을 읽고 "놀랐다"고 느끼는가? Y / N
어느 문장에서? (선택)
```

### 판정 기준

**이진 판정**: 상규가 "놀랐다"고 말하면 성공. 말하지 않으면 실패.

판정 시 주의: "이건 맞는 것 같다" ≠ 성공. "맞는 것 같다"는 거울이다. "놀랐다"는 창문이다. 구별 방법 — 읽고 즉각적으로 불편하거나 낯선 느낌이 있으면 성공 쪽이다. 읽고 "그렇지 그래"가 나오면 실패다.

**실패 시 처리**: 매칭 서사를 교체하거나(다른 작품), 구조 추출 프롬프트를 수정하거나(더 구체적인 회피 지점), 입력 텍스트를 교체한다. 3회 교체 후에도 실패하면 "이 알고리즘으로는 놀람이 생성되지 않는다"는 정보를 얻은 것이다.
