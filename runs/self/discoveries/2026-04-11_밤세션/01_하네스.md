## 역할 분담 (소넷 vs 오퍼스)

| 모델 | 역할 | 출력 특성 |
|---|---|---|
| **소넷** | 실행·외연 층 | 시장 스캔, 경쟁 제품, MVP 기능, 첫 주 실행 태스크, UX 후보, 기술 스택. "무엇을 어떻게 만들 것인가." 구체·실행 중심. |
| **오퍼스** | 비판·구조 층 | 나다움 공식 정합 검토, 거울 트랩 감별, 철학적 함정, 구조적 위험, "왜 이 제품이 상규여야 하는가." **출력은 읽는 사람에게 이의를 던지는 형태.** |

두 결과는 **별도 파일**. 상규가 아침에 두 결과를 읽고 본인이 종합. **판단 외주 금지** — 에이전트는 후보·분석·비판만 제공하고 결정은 상규.

## 트랙 A — 건강관리 앱

### 컨텍스트

- **30p와 무관한 독립 트랙.** 4월 30p 데드라인 동안은 대기 상태. 에이전트 산출물은 해동 시 재개 포인트로 사용.
- 저장 경로: `~/pp/ideas/2026-04-11_건강관리/`
- 파일명: `02_sonnet.md` (소넷), `02_opus.md` (오퍼스)

### 핵심 차별점 (밤 세션 도달, 반드시 이어받아 전개)

1. **실행 트리거 (Decision Bypass)** — "도저히 못 하겠으면 이 세 가지만 하고 자세요." 대부분 건강 앱은 정보를 주고 결정을 사용자에게 떠넘기는데, 무너지는 순간엔 결정할 기력이 없다. 그 지점에서 **대신 결정해주는 앱은 거의 없다.** 상규 자신 원칙 "지친 상태 판단은 왜곡"이 제품 핵심 기능으로 번역되는 지점.

2. **반증 루프 (Negative Evidence)** — "이 전략은 당신에게 안 맞습니다." 대부분 건강 앱은 positive-only. 효과 없으면 조용히 사라질 뿐. 비교군 기반 탈락 판정은 **과학성을 제품 신뢰 메커니즘으로 바꾸는 길.**

### 포지셔닝·코어·관통축 전략

- **포지셔닝 (마케팅 메시지)**: 올인원. "당신의 모든 건강을 AI가 관리합니다." 랜딩·브랜드·서사 전부.
- **초기 코어 (실제 구현)**: 한 도메인부터 깊게. 사용자에겐 "다른 건 곧 나옵니다."
- **관통축**: 실행 트리거 엔진. "이 세 가지만 하세요" 로직이 수면·영양·운동 어디에도 같은 구조로 꽂힘. 도메인 추가가 코어 개조 없이 붙는다.
- 이 구조로 출시 땐 한 도메인, 6개월 후 세 도메인, 1년 후 올인원 도착. 비전 그대로, cold start 리스크 낮게.

### 규제 돌파 경로 (반드시 판단)

- **"동의"는 의료법 우회 수단이 아님.** 한국 의료법에서 "의료행위"로 해석되면 사전동의가 있어도 무면허 의료행위. FDA도 동일.
- **Theranos 경로 금지.** Uber/Airbnb와 달리 의료는 사고 한 건이 편익을 압도하는 구조라 "규제 무시 돌진"이 통하지 않는다.
- **3가지 돌파 경로 중 택1 권장:**
  - (i) **의료법 경계 밖 정면 돌파** — 수면 질/피로 회복/운동 수행능력/생활습관/멘탈 컨디셔닝. 이건 의료 아님. 여기선 공격적으로 가도 됨.
  - (ii) **전문가 매개 파트너십** — 의사·한의사·영양사 구조로 정식 편입. 느리지만 벽 돌파.
  - (iii) **해외 시장 먼저** — 미국 DTC health는 한국보다 관대. n=1000 쌓은 후 돌아오기.

### 반드시 다룰 항목

- [ ] **첫 도메인 최종 추천** — 수면 vs 다른 후보(운동 회복 / 피로 / 염증 / 영양)를 비교하고 1개 확정 + 이유.
- [ ] **한국 의료법 카피톤 가이드** — 단정형("해야 합니다") → 확률/비교형("비슷한 프로파일의 사람들은...") 문장 예시 10개.
- [ ] **cold start 단계 설계** — 초기(n=0)부터 사용자 쌓이며 개인화 강도 증가시키는 단계. 언제 어떤 알고리즘으로 교체되는지.
- [ ] **풀림 UX 자산 이식 맵** — 사다리형 결정 지원 등 재활용 가능한 컴포넌트 목록 + 어느 기능에 이식할지.
- [ ] **타깃 페르소나 1명** — 20대 후반~30대 한국인, 갓생 시도 경험자, 건강 정보 과잉 시대의 피로 상태.

### 핵심 구조

> **외부 서사 DB × 사용자 기록 → 구조 매칭**

- 취향 추천이 **아님**. "당신이 좋아할 것"이 아니라 "당신이 이미 살고 있는 삶의 원형."
- 불편한 거울 가능. 사용자가 싫어할 법한 결과가 최선일 수 있음.
- 낯설게 하기(defamiliarization)의 LLM 기반 기술 번역.
- **상규의 직접 요구 대응** (NEXT_v2.md 인용): *"나에 해당하는 것. 내가 생각하지 못한, 나의 더러운 것, 나의 정해진 것. 나의 삶 속의 통찰."*

### 풀림과의 관계 — 대체재 아닌 보완재

- 풀림 = "힘들 때 옆에 있어주기" (정서 파트너, AI 본질 위반으로 실패)
- 자극 엔진 = **"심심할 때·막힐 때·뇌가 멈췄을 때"** (발견 엔진, AI 본업)
- 두 니즈는 다르다. 자극 엔진은 풀림 실패 보상이 아니라 다른 구멍.

### 반드시 다룰 항목

- [ ] **고고학자(HARNESS_product)와의 차별 명시** — 고고학자는 *사용자 기록 내부*에서 패턴 추출(상규 카톡을 상규 자료로 분석). 자극 엔진은 *외부 서사 × 사용자 기록* 교차. 입력 공간이 다름. 다만 출력 단계(반박 루프, 심층 질문 UX)는 공유 가능.
- [ ] **30p 통합 경로 판단** — 두 옵션을 저울질:
  - **옵션 I: 독립 제품**. 외부 서사 DB를 별도 구축(문학/영화/신화). 사용자 기록과 매칭. 30p 외부.
  - **옵션 II: 30p 내부 실험으로 수렴**. 30p의 30명 캐릭터가 "외부 시각"을 담당. 상규 자료를 30명이 각자 해석. 30p 다음 실험 후보 (a)의 변형. 기존 인프라 재활용.
  - 각 옵션의 장단점 명시 + 권장안.
- [ ] **초기 큐레이션 텍스트 DB 후보** (옵션 I 경로) — 구체 작품 10개 이상. 카뮈·헉슬리·장자·셰익스피어·SF·성서·동아시아 고전 등에서. 각 작품이 어떤 **구조**를 제공하는지 한 줄.
- [ ] **구조 매칭 알고리즘 개요** — 사용자 기록의 "구조"를 어떻게 추출(결정 루프/관계 형식/감정 주기/주장 패턴)하고, 외부 서사의 구조와 어떻게 매칭할 것인가. LLM 프롬프트 레벨 의사코드.
- [ ] **상규 본인 데이터로 프로토타입 1회 실행 설계** — 입력(어떤 자료 넣을지), 처리(어떤 프롬프트), 출력(어떤 포맷), 판정 기준(상규가 "놀랐다"고 느끼는지).

## 실행 규칙

1. **각 에이전트는 자기 트랙만** 본다. 크로스 트랙 최적화는 상규가 아침에 직접.
2. **결과 파일은 반드시 지정 경로에 저장.** Write 툴 사용.
3. **세션이 멈추면 상규가 내일 아침 동일 하네스로 재개 가능하게** 자기 완결성 유지. 중간 상태 남기지 말 것.
4. **의문 발생 시 합리적 가정 + 가정을 출력에 명시.** 상규한테 질문 돌려보내지 말 것 (자고 있음).
5. **나다움 공식(기존 나 × 새로움)에서 이탈 금지.** 이 공식이 출력의 필터.
6. **완료 후 짧은 요약 1-2문장만 상위 컨텍스트로 리턴.** 긴 응답 금지.
7. **상규의 정체성 원칙 위반 금지**: 아부 금지, 거울 모드 금지, 상담 어휘 금지, 걱정 언어 금지(`self/README.md` 참조), 휴식 권유 금지.
