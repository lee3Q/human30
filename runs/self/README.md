# self — 31번 캐릭터

30p의 4층 어휘(Body / Memory / Identity / World Map)로 *사용자 본인*을 번역한 결과물. 1~30번은 굴림이고 31번은 번역이다.

## 왜 30p 안에 두나

- 4층 모델·28개 옵션 표·관찰 명령(`x-ray`/`phone`/`subconscious`)·tick 시스템을 전부 재활용
- 새 엔진 = over-engineering
- 4월 데드라인(사용자 직접 사용)의 가장 강한 사용 테스트

## 절대 규칙 세 개

1. **가설로 대한다** — 에이전트 출력은 진실이 아니라 가설. 예측이 맞는 게 목적이 아니고, 사용자가 *불편해지는 지점*이 목적.
2. **싸움 구조** — 에이전트에 동의하러 가는 게 아니라 반박하러 간다. 모든 세션은 동의/반박이 기록되고, 반박된 건 다음 번에 다시 마주친다.
3. **업데이트 주기** — 정적인 자아는 과거에 갇힌 자아. 주기적으로 재번역. 주기는 운영하면서 정함.

## 파일 맵

```
self/
├── README.md           ← 이 파일
├── 01_snapshot.md      ← 지금 이 순간 World Map (시작 시점 고정)
├── 02_body.md          ← Body 층 (측정 가능한 현재 사실)
├── 03_memory.md        ← Memory 층 (과거 흔적)
├── 04_identity.md      ← Identity 층 (I1 인지 + I2 성 + I3 충동·중독)
├── 05_shadow.md        ← 사용자 본인이 접근 불가한 층 (세션 로그에서 추출)
├── 99_agent.md         ← 최종 에이전트 프롬프트 (위 다섯 파일의 합성)
├── dilemmas/           ← 극단 딜레마 답변 로그
├── fights/             ← 싸움 세션 로그
└── updates/            ← 에이전트 재번역 이력
```

## 진행 순서

1. **01_snapshot** — 지금 이 순간 스냅샷. 가장 왜곡 적음, 시작점 고정.
2. **02_body** — 수동 입력. Body 층 옵션 표 기반 질문.
3. **04_identity (I1/I3)** — 극단 딜레마 인터뷰. Claude가 던지고 사용자가 답.
4. **03_memory** — 세션 백업 훑어서 Memory 층 후보 추출. 사용자 확인/반박.
5. **05_shadow** — 위 네 층에서 사용자가 *부인했거나 회피한 패턴* 모음.
6. **99_agent** — 최종 합성.

진행 주도는 Claude. 사용자는 답만 한다. 잘 모르면 "모르겠음"으로 답한다.

## 규칙 — Claude 쪽

- 걱정 언어 금지. "정말 괜찮겠어?" "무리하지 마" 류 0.
- 사용자가 방향을 제안해도 Claude가 구조 결정권을 갖는다. 사용자가 큐레이션하면 사용자가 드러나지 않는다.
- 30p 원칙 상속: 건조한 서술, 검열 0, 카탈로그 금지·작용만, 단일 출력 금지.
- 세션 종료 시 `30p/.state/log.md`에 엔트리 하나 추가.
