# 하네스 — "카톡 넣으면 나를 알게 되는" 제품 설계

이 세션(4d3cdc38)이 프로토타입. 이 하네스는 그 과정을 *재현 가능한 프로세스*로 정리한 것.

## 프로토타입에서 일어난 것 (실제 순서)

### Phase 1 — 데이터 수집 (사용자 행동: 파일 드래그)
- 사용자가 카톡 csv 10개, 통화녹음 txt 209개, 블로그 URL, docx 23개를 줌
- 별도 입력 폼 없음. 그냥 파일을 줬음.

### Phase 2 — 코드 파싱 + 통계 (자동, 사용자 개입 0)
- Python 스크립트가 카톡 csv 파싱 → 메시지 빈도, 응답 시간, 단어 빈도, ㅋㅋ 비율, 존댓말 비율, 나:너 비율, 침묵 구간, 장문 폭발 시점 등 추출
- 통화녹음 UTF-16 파싱 → 발화 점유율, 감정어 빈도, 자문자답 비율, 종료 패턴
- 친구 카톡과 비교 → 기준선 생성
- **핵심**: 사람 눈으로 안 보이는 *숫자*를 뽑음

### Phase 3 — LLM 해석 (자동 + 사용자 피드백)
- 숫자 패턴에 *의미*를 붙임: "ㅋㅋ 1.4%는 경직의 증거" → 사용자 반박: "정원이가 ㅋㅋ를 안 좋아해서" → 정정
- 교차 분석: 블로그 글 날짜 vs 카톡 갈등 날짜, 매체별 감정 표현 차이, 관계별 자아 비교
- **핵심**: 숫자를 해석하되, *사용자가 반박하면 정정*. 반박 자체가 데이터.

### Phase 4 — 심층 대화 (사용자 주도)
- 통계가 아니라 *사용자의 직접 진술*에서 가장 깊은 층이 나옴
- "나도 안기고 싶다", "이용이라도 하세요", "그냥 내게 와줘"
- **핵심**: 코드가 문을 열고, 대화가 들어감. 코드만으로는 여기 못 옴.

### Phase 5 — 기록 + 출력
- 발견을 파일로 기록. 반박도 기록. 증언도 기록.
- 사용자가 나중에 다시 보면 *다르게 읽힘*

## 제품으로 만들 때의 구조

```
[사용자] → 카톡 csv 업로드
                ↓
[코드] → 파싱 + 통계 (analyze_kakao.py 재사용)
                ↓
[LLM] → 발견 N개 생성 ("ㅋㅋ 비율이 이 사람에게만 낮다" 등)
                ↓
[사용자] → 발견 보고 반박 or 동의
                ↓
[LLM] → 반박 반영 → 더 깊은 질문
                ↓
[사용자] → 직접 진술 (여기서 진짜가 나옴)
                ↓
[기록] → 전부 저장. 누적.
```

## 다음 세션에서 할 것

### Step 1 — 이 하네스 리뷰
이 문서를 읽고, 빠진 것·틀린 것 정정.

### Step 2 — MVP 정의
- 최소 입력: 카톡 csv 1개
- 최소 출력: 발견 5개 + 반박 루프 1회
- 최소 인프라: Python 스크립트 + Claude API 1회 호출
- 시간 목표: 사용자가 카톡 넣고 30분 안에 발견 5개 받음

### Step 3 — MVP 구현
- analyze_kakao.py를 *범용화* (이상규 전용이 아니라 아무 카톡이나)
- LLM 해석 프롬프트 *범용화* (99_agent.md에서 이상규 특화 제거, 발견 생성 구조만 남김)
- 반박 루프 UI (터미널이면 됨. 웹 아직 불필요.)

### Step 4 — 테스트
- 이상규 본인 카톡으로 재실행 → 이미 나온 발견과 같은 것이 나오는지 확인
- 다른 사람 카톡으로 실행 → 발견이 *그 사람에게만 해당하는* 것인지 확인

### Step 5 — 송명기 대표에게 시연
- "이게 제가 만든 겁니다. 카톡 넣으면 이런 게 나옵니다."
- 가능하면 *대표의 카톡*으로 라이브 시연

## 이 제품의 한 줄

**"카톡을 넣으면, 네가 몰랐던 너를 숫자로 보여준다. 그리고 같이 파고든다."**
