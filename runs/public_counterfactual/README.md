# Public paired counterfactual evidence

All inputs are fictional. The `body`, `memory`, `identity`, and `world_model`
files in this directory are hand-authored fixtures. They exercise the
one-axis constraint, hashing, and independent evaluator without pretending
that the answers came from a model.

`actual_codex_body/` records one pair generated by real `gpt-6-sol` Codex CLI
calls. The CLI has no sampling-seed option. Its manifest sets
`effective_model_seed` to `null` and records the CLI version separately from
the unavailable exact model snapshot.

`actual_seeded/` records four more real model pairs, one per condition axis.
Each pair used the same `openai/gpt-4.1-mini` model, scenario, prompt template,
requested seed 42, temperature 0, and JSON schema for both arms. Only the
named condition changed. OpenRouter's model catalog advertised seed support;
the requests, response IDs, returned model/provider, usage, condition vectors,
prompts, and hashes are recorded in each manifest. The provider did **not**
report an effective seed or exact model snapshot. A third call repeated the
baseline with the same seed: two of four repeats matched exactly and two
differed. Therefore the manifest records the requested seed and repeat result,
not a guarantee of bit-for-bit deterministic sampling.

From the repository root:

```sh
uv run pytest -q
python3 -m scripts.verify_public_pairs --out runs/public_counterfactual/verification_receipt.json
```

To regenerate the seeded real-model examples, set `OPENROUTER_API_KEY` in the
environment and run:

```sh
python3 -m scripts.run_openrouter_pairs --temperature 0 --out runs/public_counterfactual/actual_seeded
```

Only the synthetic scenario and prompts go to the API. The key is never saved
in run artifacts. API calls may incur a small cost. To regenerate the Codex
example with an authenticated CLI:

```sh
python3 -m scripts.run_codex_pair --axis body --model gpt-6-sol --seed 42 --out runs/public_counterfactual/actual_codex_body
```

The independent evaluator reads structured outputs and scenario constraints.
It ignores any generator self-assessment. Unknown IDs, missing fields and
out-of-range emotions fail. The verifier reopens stored files, checks hashes,
reconstructs seeded requests, and re-evaluates outcomes. These are Stage 1
execution and audit examples. Paired output differences alone do not prove a
causal effect of a condition: equal-seed repeats can differ. Repeated runs,
uncertainty estimates, and independent human review belong to Stage 2.
